# 코드리뷰 가이드라인 (Code Review Guideline)

두 소비 프로젝트(웹 퀴즈 앱·보드형 웹 게임)의 PR에 달린 자동 코드리뷰 봇 인라인 지적
**391건(P1 57건)** 을 전수 클러스터링(커버리지 391/391)해, 관점을 "어떻게 만들까(예방)"에서
**"리뷰어가 diff에서 무엇을 잡아내야 하는가(탐지)"** 로 재정립한 단일 출처다. 각 불릿은
"이런 diff를 보면 → 이 결함을 의심·확인하라"로 읽는다. 끝의 `(N건)`은 근거 지적 수, `P1`은
치명 등급 포함, 태그 `(원칙)`은 코퍼스 무관 교차 교훈(개수 근거 없음)을 뜻한다.

이 문서는 **하나의 파일이 두 렌즈로 쓰인다**: `$pr-self-loop`·`$pr-review-check-*`의 격리
리뷰어와 role 문서는 이걸 **탐지 렌즈**로(부록 A), `$feature-develop`의 설계·구현·자체 검증
단계는 같은 규칙을 **예방·자가리뷰 체크리스트**로 참조한다(복제 금지). 예전 이름은
`implementation-guidelines.md`였다.

## 코퍼스 갱신 기록 (high-water mark)

다음 갱신 때 **아래 PR 번호 이후의 PR에 달린 봇 인라인 리뷰만** 확인하면 된다(전수 재수집 불필요).

| 소비 레포 | 최종 반영 PR | 봇 인라인 코멘트 근거 |
| --- | --- | --- |
| `pokequiz-hub` | #127 | 197건 |
| `cross-wars` | #75 | 195건 |

- 봇 author: `chatgpt-codex-connector[bot]`. 수집 endpoint: `repos/<owner>/<repo>/pulls/comments`
  (레포 전체 인라인 리뷰 코멘트)를 봇 author로 필터. `pull_request_url`의 말미가 PR 번호다.
- 갱신 절차: 위 번호 초과 PR의 봇 인라인 코멘트만 수집 → surface×family로 클러스터 → 새 family는
  R1–R7 중 하나로 환원하거나 새 detector로 확장 → 해당 섹션 `(N건)` 갱신 → 이 표의 PR 번호 갱신.

## 이론적 토대 — 근본 실패 계층(R1–R7)과 완전성

모든 결함은 §0 코어 렌즈(=원칙)의 **부정형**인 7개 근본 계층 중 하나로 환원된다. 이 계층이
"리뷰어가 무엇을 놓치면 안 되는가"의 뼈대다.

- **R1 단일출처 붕괴** — 같은 사실(수치·공식·규칙·문구)이 둘 이상에 존재하고 함께 안 움직여
  드리프트한다. (§1·§2)
- **R2 경계 불신 실패** — 신뢰 못 할 입력이 bounded 검증·인가 없이 역참조·DB·메모리에 도달한다.
  방어 코드 자체가 unbounded면 방어가 아니다. (§3, §9의 입력 계층)
- **R3 왕복 미완** — 저장/캐시/설정/진입/포커스 중 한 방향만 만들어 복원·무효화·해제·이탈·복귀가
  빠진다. (§5·§8·§4)
- **R4 파생·동시성 정합 붕괴** — 파생값을 입력 변경에 재동기 안 하거나, 복원 검증이 얕거나,
  read-check-write가 비원자라 경합·stale·clobber가 난다. (§5·§6)
- **R5 규칙 커버리지·경계 불완전** — 도메인 규칙이 케이스·경계·우선순위·계층 임계를 다 못 덮어
  무효 입력이 성공으로 승격되거나 게이트가 다운스트림과 어긋난다. (§4·§10)
- **R6 시간·순서 가정** — 서로 다른 시계·스케줄러·이벤트 순서·애니메이션 수명을 가정한다. (§6)
- **R7 극단 시각·접근 경로 미검증** — 극단 뷰포트·기하 측정·포커스·SR·IME·로케일 경로를 기본
  환경에서만 확인하고 배포한다. (§7·§8)

**완전성:** 10개 surface가 391 인스턴스를 정확히 분할하고(각 인스턴스 1 surface), surface 내부는
family로, 각 family는 R1–R7 중 하나로 환원된다. 새 결함은 반드시 기존 surface·family에 안착하거나
R1–R7 중 하나의 새 detector로 확장된다(계층의 개방적 완전성). 그래서 리뷰는 "이 diff의 surface가
무엇인가 → 그 섹션의 detector로 훑는다"로 체계화된다.

## 로딩 규칙 (토큰)

**전체를 항상 로드하지 않는다.** §0 코어 렌즈 + 아래 표면 인덱스에서 이번 리뷰가 건드리는
diff의 표면만 골라 읽는다. `$feature-develop` 설계 단계가 섹션을 골라 브리핑에 발췌하면,
fan-out된 서브에이전트/리뷰어는 이 파일을 다시 열지 않는다.

| 리뷰 대상 diff가 건드리는 표면 | 섹션 |
| --- | --- |
| 동작·수치·규칙 변경으로 스펙/문서/문구/라이선스가 낡을 수 있는 diff | §1 |
| 같은 값·규칙·판정이 두 곳 이상에 등장하는 diff | §2 |
| 공개(특히 무인증) API·서버 경계·검색/목록 쿼리 | §3 |
| 상태 기계·플로우 종결·오류 분류 | §4 |
| 저장·복원·동시 쓰기·이탈 시 flush | §5 |
| 타이머·애니메이션·async 시퀀스 | §6 |
| 레이아웃·오버레이·뷰포트·스크롤·기하 측정 | §7 |
| 키보드·포커스·스크린리더·IME·로케일 | §8 |
| 데이터 생성 스크립트·파이프라인·캐시 | §9 |
| 게이트·배포·도메인 전환·릴리스 산출물 | §10 |

## 0. 코어 렌즈 (모든 diff에 적용)

1. **코드가 바뀌면 그 사실을 서술하는 문서·문구도 같은 diff에 있는가.** 한 곳에만 남은 옛
   서술을 발견하면 회귀·기만의 씨앗으로 지적한다.
2. **같은 사실이 두 곳에서 계산·서술되는가.** 이중 정의는 반드시 드리프트한다 — 파생 아닌
   하드코딩 복제를 의심한다.
3. **경계로 들어오는 값을 적대적 입력으로 검증했는가.** 방어 코드 자체가 bounded인지까지 본다
   (검증하다 OOM 나면 방어가 아니다).
4. **한 방향만 만들지 않았는가.** 저장↔복원, 설정↔해제, 진입↔이탈, 캐시↔무효화가 한 단위로
   같은 diff에 있는지 확인한다.
5. **극단에서 대조했는가.** 스펙 한정어 문구 단위 대조 + 최장 입력·최소 뷰포트·다른 로케일·직접
   URL 진입을 diff가 견디는지 본다.
6. **"유저 적을 때는 괜찮다"로 미룬 확장성 결함이 없는가.** 규모를 목표하는 코드의 확장성 유예는
   목표와의 모순으로 잡는다.

## 1. 스펙·문서·사용자 문구 동기화

- diff가 동작·수치·규칙을 바꿨는데 그것을 서술하는 PRD·ADR·패치노트·위키·테스트 설명·후속
  TODO·발효일·사이트맵 lastmod가 같은 diff에 함께 안 움직였으면 → 옛 서술이 정본으로 남아
  회귀·기만을 부른다. repo-wide 검색으로 낡은 서술을 지적하라. (12건, P1)
- 승인 스펙의 한정어("최초 1회만"·"루트 진입에만"·포함/제외 목록)와 diff의 가드가 문구 단위로
  어긋나면 → 조건마다 대응 장치가 1:1로 있는지 확인하라. "대체로 동작함"에서 한정어 누락을
  의심하라. (8건, P1)
- 사용자 노출 문구가 미구현 기능(보너스 점수·색상 처리)을 약속하거나 실제 판정과 다른 규칙을
  서술하면 → 런타임 경로가 그 플래그를 실제 소비하는지, 모든 로케일·프리렌더/런타임 이중 소스에
  같게 반영됐는지 대조하라. (9건)
- 데이터 필드 제거/스키마 변경 diff → 그 필드를 읽는 문서·재현 스크립트·자동 연결(asset slot)이
  여전히 실행되는지 grep하라. 계약 문구만 남으면 에러 없이 조용히 어긋난다. (4건)
- **라이선스·크레딧·NOTICE 문서 diff** → (a) 문서가 나열하는 파일·API·자산이 저장소에 실제
  존재하는지 대조하고(존재하지 않는 항목을 열거하면 문서가 거짓), (b) "상업적 사용 가능"·"운영자
  제공" 같은 포괄 선언이 **자산별 출처 URL·저작자·정확한 라이선스**로 뒷받침되는지 확인하라 —
  근거 없는 포괄 선언은 배포/라이선스 감사에서 깨진다. (2건, P1)
- 법적·정책 문구에 수집/광고/상업 조항이 추가되면 → 목적·한정 문단, '비영리'·'그 외 사용 없음',
  적용 범위(코드가 실제 트리거하는 라우트)와의 정합을 모든 로케일에서 검증하라. (4건)
- raw 단위 추가/변경 diff → wiki index area 등재·ingest 짝, 승인 문서 내 자기모순 조항, raw NUL
  임베드(git이 binary로 취급해 검색에서 사라짐)를 함께 확인하라. (5건)

## 2. 단일 출처·파생 일관성

- 같은 값·공식·상수(랭킹 가중치·tie-breaker·연락처·카운트·튜토리얼 맵·지속시간)가 두 파일/두
  경로에 하드코딩돼 있으면 → 공유 정의 파생인지, 드리프트 회귀 테스트가 있는지 의심하라. (7건)
- UI·계측·시뮬 로직이 앱 실행 엔진과 다른 정규화(정규화 미적용·pre-ability 값)를 쓰면 → 플레이어
  가시 신호와 같은 규칙을 공유하는지 대조하라. (2건)
- 입력에서 파생된 표시값을 이벤트 시점에 스냅샷하고 로케일/입력 변경에 재동기하는 effect가 없으면
  → 즉시 무효화·재계산 누락을 지적하라. 디바운스된 판정(연결성·생성 가능 여부)을 입력/설정 변경
  후 **서명(signature) 재확인 없이** 재사용하면 "준비됨" 표시인데 제출이 no-op이 된다. (3건)
- 문자 길이 단위(코드포인트 vs UTF-16)·유니코드 정규화(NFC/NFD)·표시 자릿수가 계층마다 다르면 →
  같은 값이 다른 키가 된다. 반대로 한 포매터의 `maximumFractionDigits` 상한이 서로 다른 작은 값을
  같은 문자열로 뭉개는지도 본다(정밀도 유실). 전 계층 단일 계약을 확인하라. (4건)

## 3. 경계 입력 검증·서버 방어

- 공개 입력이 역참조·DB 전달 전 완전 검증 없이 쓰이면 → 숫자는 `Number.isFinite`·정수성·부호·경계
  동등값·대상 컬럼 타입 범위(int4/int8), null 본문 deref, whitespace-only, 형식만 검사한 date/id를
  의심하라(NaN은 모든 비교에서 false라 가드를 침묵 통과). 500이 아니라 400으로 끝나야 한다. (9건)
- 클라이언트 공급 가변 크기 필드에 서버 하드 상한이 없거나 본문 파싱 전 바이트·청크 상한이 없으면
  → `[...str]`·`request.json()`·per-chunk 누적이 거부 판정 전에 OOM. 길이 검사도 상한+1까지만
  소비하는 bounded 방식인지 본다. (9건, P1)
- 저장소가 거부하는 문자(U+0000·고립 UTF-16 서로게이트)가 본문·검색어·커서·경로 세그먼트 중 한
  경로만 걸러지면 → 공용 검증으로 **모든** 경로에 일괄 적용됐는지 확인하라. 한 경로만 고치면
  나머지에서 같은 500 재발. (7건)
- 상태 변경 공개 POST에 Origin/Content-Type/소유자/권한 스코프/예약어 검사가 없으면 → CSRF·타인
  리소스 덮어쓰기·예약 ID 충돌·통계 오염을 의심하라. upsert 충돌 분기의 소유자 미비교는 접근 검사가
  아니다. (6건, P1)
- 클라이언트 강제 정책(필수값·범위·min-length·sanitize)을 서버가 재검증 안 하거나 집계에 클라 값을
  그대로 기록·정본 어휘와 교집합 없이 저장하면 → 직접 호출이 통계를 영구 오염. sanitize한 값이 아니라
  raw를 저장하는지도 본다. (6건, P1)
- 검색/목록 API가 ILIKE 메타문자(`%`·`_`) 미이스케이프, nextCursor 미소비, 절삭 커서, 인덱스 컬럼
  순서 부적합이면 → 와일드카드 주입·미발견·행 누락·seq scan. 커서 상한 경계(`<=`)가 페이지 초과를
  허용하는지도 본다. (7건)
- 부분 실패를 성공 200/기본값으로 반환하거나 2xx 파싱 실패를 not-found와 혼동하거나 timeout/Abort
  없이 응답을 게이트하면 → 재시도 불가·영구 pending을 지적하라. (6건)

## 4. 상태 기계·오류 분류·종결 상태

- 오류 분류 우선순위 계약과 가드 실행 순서가 어긋나면 → 무효 입력이 timeout·게임오버 같은 정상
  종료로 승격되거나 전송 실패가 도메인적 부재(not-found)와 혼동되는지 본다. pending/실패/성공을
  구분하는지 확인하라. (5건)
- 종결 상태에서 변경 입력 경로가 핸들러 진입에서 차단되지 않거나(오버레이로 가리는 것은 차단 아님)
  종료 시점 표시값이 freeze 안 되면 → 완료 보드 편집·게이지 리셋을 의심하라. (4건)
- 원샷 억제 플래그에 해제, 라우트 정체성 변경에 리셋, 중도 이탈에 저장, 초기 시드에 전 진입점 보장이
  빠지면 → 재진입·직접 URL 고착·exploit. (4건)
- 규칙 엔진에서 주 결과가 무효인데 파생 효과를 억제 안 하거나, '전체' 플래그 범위를 미열거하거나,
  연속 수치를 exact-match로 분류하거나, 주입 의존성을 경로별로 우회하면 → 부당 단서·오분류·복원
  불일치를 잡는다. (4건, P1)
- 게이트가 다운스트림 실사용 불변식과 다른 임계·커버리지를 쓰면 → create 게이트가 length·연결성을
  미검사해 load가 거부할 항목을 통과시키는지, 도메인 무효(NaN·음수·degenerate 경계)가 성공으로
  새는지 본다. (9건, P1)

## 5. 영속화·복원·동시 쓰기

- 복원 데이터가 원소별 shape·값 도메인·현재 정본과 대조 검증 없이 기본값으로 보정되면 → 통째 폐기
  후 안전 폴백이어야 한다. 환경 의존 글로벌(localStorage)은 획득 시점부터 가드됐는지 본다. (8건)
- write API에 read 짝이 없거나(dead write) 입력 UI가 영속 payload에 미배선이면 → 저장되는 척 버려지는
  기만. 폴백 저장소의 read/write 대칭·최신값 우선순위, sent 분기의 refetch 폴백도 확인하라. (6건, P1)
- 완료 레코드가 revision/상태 우선순위 가드 없이 뒤늦은·미완료 쓰기에 덮이거나 count(*)-후-INSERT가
  비원자면 → 다중 탭 경합·동시 초과·clobber. 복원 시 권위 플래그가 진행 스냅샷을 이기는지, 늦게
  도착한 GET이 최신 상태를 덮는지 본다. (9건, P1)
- 이탈 경로(탭 숨김·페이지 종료·SPA 내부 라우팅·언마운트)에서 flush가 누락되거나 unload가 읽는 미러
  상태가 비동기로만 갱신되거나 라이프사이클 이벤트가 잘못된 타깃에 등록되면 → `pagehide`는 SPA 내부
  이탈에서 안 뜬다. (4건, P1)
- **클라이언트가 로컬 전용 ID(로컬 시드·미영속 엔터티)를 참조하는 레코드를 서버로 보내면** → 그 ID의
  DB 행이 없어 FK 404·조용한 통계 유실. "source-agnostic 전송" diff에서 참조 대상이 영속 행을 갖는지,
  로컬-only 엔터티가 전송 전 영속화·매핑되는지 확인하라. (1건, P1)
- 쓰기 "접수"와 "커밋 완료"를 미구분(요청 성공에서 resolve·premature done 플래그), 재시도 비멱등(제출
  시 UUID 재발급), dev/마이그레이션이 실사용자 상태 오염, 조회 함수가 상태 변경 로더 호출이면 →
  중복 행·관찰자 효과를 잡는다. (13건)

## 6. 비동기·타이머·스케줄링

- 타이머가 벽시계 종료 시각 차이가 아니라 틱 누적으로 계산하거나, 지속시간을 CSS/코드에 이중 정의하거나,
  표시와 판정이 다른 시작 기준을 쓰면 → 백그라운드 스로틀 드리프트·판정 불일치. 매 틱 타깃 재계산으로
  카운트다운이 0을 못 넘는지, DST 오프셋·**로컬 시각에서 파생한 값을 서버 UTC 허용창과 비교**하거나 한
  논리 연산이 **now()를 두 번 독립으로 읽어 날짜 경계**를 넘는지도 본다. (7건, P1)
- 순차 국면 타이머를 시작 시 동시 예약하거나, rAF↔setTimeout 순서에 의존하거나, 공유 완료 플래그가
  형제를 조기 절단하면 → 국면 붕괴·잔상. 앞 국면 콜백 안 체이닝인지 확인하라. (5건)
- 주입 async rejection을 error 상태+재시도로 흡수 안 하고 catch로 삼키거나 응답 경로에서 best-effort를
  await하면 → pending 영구 고착·응답 지연. 동기 try/catch가 async reject를 놓치는지 본다. (3건, P1)
- 첫 화면에 반영될 값을 effect에서 늦게 세팅하거나 terminal 값을 미동기하면 → blank frame·플래시.
  캐시 쓰기 후 무효화 누락·waitUntil 경합·재읽기 미재발행·cold-cache stampede·브라우저 max-age도
  stale로 잡는다. (10건)
- 오디오/프리로드가 늦게 시작·완료 게이트 없음·in-flight 미중복제거·배치 콜백 재생·mute가 신규만·resume
  전 스케줄·상태 enum(iOS 'interrupted') 미처리·**재진입 창(started 플래그가 뒤집히기 전 반복 Enter가
  triggerStart 재호출)**·**재사용이 완료 콜백을 드롭**하면 → 사운드 유실·중첩·복구 실패. (14건)
- boolean 게이트에 묶인 CSS 애니메이션이 이미 true인 상태에서 다시 트리거되면 no-op → 클래스
  remove/re-add나 key 재부착으로 매 트리거 재생을 보장하는지 본다. (1건)

## 7. 레이아웃·뷰포트·기하 측정

- 크기 무제한 콘텐츠에 minScale 하한+overflow 클리핑 조합이 보이면 → 실제 fit 허용/스크롤 탈출구가
  있는지, 최장 입력×최소 뷰포트 경계를 견디는지 본다. DOM 존재만 보는 테스트는 시각 클리핑을 못
  잡는다. (5건, P1)
- 고정 크기 세로 스택·nowrap 행이 320px·가로 모드·최장 로케일 라벨 합산을 미검증하면 → 오버플로/
  클리핑/컬럼 붕괴(auto-fit min-width 계산 오류). (6건)
- 앵커 rect·offsetTop 스냅샷을 캐시 재사용하거나 window 치수로 오버레이를 배치하면 → 리사이즈·회전·
  소프트 키보드·스크롤에서 재측정·`visualViewport`(offset 포함) 기준인지 본다. 특히 iOS 소프트
  키보드 다중 프레임에서: **경계 연산자(`>=` vs `>`)가 닫히는 프레임을 잘못 허용**하는지, **높이가
  같은 프레임도 offsetTop을 갱신**하는지, **닫힘/복원 방향 프레임이 유지 중인 height를 덮어쓰지**
  않는지, **핀치-팬(offset 감소) vs 키보드-닫힘을 구분**하는지, height만 freeze하고 offset 미freeze는
  아닌지를 프레임 단위로 확인하라. (13건, P1)
- 중첩 오버레이 최대 크기를 부모 기준으로 잡거나, `min-height:0`+`overflow-y:auto` 내부 스크롤이 없거나,
  앵커 정렬로 최소 높이 미달 시 전체 영역 폴백이 없으면 → 스크롤 0 붕괴로 마지막 항목 도달 불가. (6건)
- 측정이 이전 인라인 제약을 미해제하거나 absolute 자식을 제외하거나 내용 변화를 미재측정(ResizeObserver)
  하면 → 잘못된 배치·자연 크기 미복원. (6건)
- 카메라/스크롤 목표가 "지점 중앙 정렬"(바운딩 박스 아님)이거나 보간 중 좌표계를 재기준화하면 →
  클리핑·텔레포트. (2건, P1)
- 자릿수 증가 숫자·지연 이미지 공간 미예약, reduced-motion에서 transition 잔존·CSS cascade 역전,
  display:none로 flex basis 붕괴면 → CLS·모션 누락. (7건)
- SPA 화면 전환(라우트 교체·내부 상태 전환·컨테이너 내 교체)마다 스크롤 상단 리셋이 없거나
  `preventScroll`가 제거한 부작용을 대체 안 하면 → 상단 잘림. (4건)
- 항상 접근 가능해야 할 탈출구/CTA가 오버레이에 가리거나 미노출이거나, local 데이터를 remote 완료에
  게이트하면 → escape 상실·빈 화면·유효 값 폐기. (5건)

## 8. 접근성·포커스·입력·로케일

- 포커스 요소를 언마운트/비활성화하는 전환(제출·닫기·화면 전환)에서 새 요소로 명시 이동·복귀가
  없거나 복원 대상이 DOM 연결됐는지 미확인이면 → body 유실로 탐색 재시작. 흐림 효과가 포커스 링을
  지우는지도 본다. (8건)
- pointerdown/keydown로 활성화를 재구현하면 `event.repeat`·primary 버튼·보조기술 합성 click을 재구현해야
  한다 → 모든 이벤트 경로에 가드가 있는지, hover↔click 충돌·pointerType 미검사(하이브리드 터치)를 잡는다. (9건)
- IME 조합 이벤트(compositionend·keyCode 229·isComposing) 순서를 신뢰하거나 자체 추적을 안 쓰면 →
  제출 유실(플랫폼별). 클라 가드가 도메인 실패 분기를 도달 불가로 만드는지도 본다. (4건, P1)
- ARIA/키보드 시맨틱을 플랫폼 실동작으로 미검증하면 → Enter+Space 둘 다, aria-hidden이 유일 접근
  표현을 지우는지, range 속성이 비-range role에 붙었는지, aria-label이 이름 소지 role에 있는지,
  반응형 숨김 후 접근명 유지를 본다. (6건)
- 반복 이벤트 피드백(라이브 영역·애니메이션)이 실제 DOM 변화 없이 발생하면 → 동일 텍스트는 SR가
  공지 안 한다. 세대 key·빈 마운트 후 채움인지 확인하라. (2건)
- 지원 로케일을 검색 매칭·표시 텍스트·aria-label·툴팁까지 전 소비 지점에 전수 적용 안 하고 기존
  헬퍼 두고 원본 값을 직접 쓰면 → 그 로케일 사용자는 기능 자체 불가. (3건, P1)

## 9. 데이터 생성 파이프라인·캐시 수명주기

- 캐시 키에 소스 리비전·산출 스키마·생성 로직 버전이 없거나 필수 필드 추가 시 네임스페이스 미범프면
  → 소스/정책 변경 후 stale 재사용. 최초 채움(제어권 획득 전 요청)·배포 시 무효화까지 설계됐는지 본다.
  "`--fresh`를 기억해야 함"은 실패한다. (6건)
- 포함/필터 정책 변경 diff → 같은 파이프라인의 스키마 검증기·캐시 버전이 함께 갱신됐는지 확인하라 —
  둘을 함께 안 풀면 재생성이 새 정책을 우회한다. (2건, P1)
- 재현성 파이프라인에서 외부 소스가 floating ref면, 생성물↔커밋물 미세 표기(전각/반각·대소문자)가
  불일치하면, 변형 병합 시 이름 필드가 미정규화면 → 왕복 재현성 붕괴·검색 실패. (5건)
- 그래프/변형 엔터티의 파생 속성이 순회 범위(계보 전체 vs 자기 노드·형제 분기 누출)나 매칭 키(coarse
  식별자)를 스펙과 대조 안 하거나 부모 상속·명명 휴리스틱을 쓰면 → 형제 form 오상속·무효 엔터티
  유입. 변형 도입 세대 등 override 속성을 base로 읽는지 본다. (8건, P1)
- 데이터를 복수 풀로 분할하면서 소비처(조회·게이트·집계·라벨)가 합집합/부분집합 중 무엇을 쓰는지
  미명시·불일관이거나 표시명 단사성 미보장이면 → 언더카운트·not-in-dictionary·이름 붕괴. (3건)
- 스냅샷이 비결정적(현재 전량 재계산)이거나 크로스쿼리 스냅샷이 불일치하거나 upsert 후 파생 집계 행을
  미정리하면 → 공유 URL desync·denominator 불일치·stale Top N. (5건)

## 10. 검증 게이트·릴리스·전환 절차

- 단계별 게이트가 개수·존재 같은 대리 지표만 검증하거나 불변식 미보장 조회가 fallback을 반환하면 →
  "통과했지만 못 쓰는" 데이터. 실패를 삼키며 분모를 고정하는 계측, placeholder를 영구 불변식으로 박는
  brittle 테스트도 잡는다. (3건, P1)
- **게이트가 무엇을 검증 안 하는지 안다.** 빌드 타입 패스가 테스트 파일을 제외하면 green ≠ 타입 안전 —
  `tsc --noEmit`(동등물)을 커밋 전 별도로 돌리는지 본다. (원칙)
- DNS 위임·프록시 전환처럼 실행 즉시 실트래픽이 바뀌는 단계는 준비/활성화 분리와 모든 검증(레코드
  대조·인증서 active·proxy status)이 전환보다 앞인지, 자동 스캔이 아니라 명시 대조 게이트인지 본다. (4건, P1)
- 리다이렉트 문법·경로 매칭·URL 정규화처럼 벤더마다 다른 세부는 다른 플랫폼 관례 이식이 아니라 공식
  문서·실측인지, 플랫폼 정규화가 canonical·사이트맵과 최종 URL 기준으로 어긋나는지 본다. (3건, P1)
- 심볼 삭제/리네임 diff → 모든 참조가 같은 변경에서 전환·빌드 통과했는지, 새로 정의한 스타일·리소스가
  실제 참조·적용 지점까지 연결됐는지 저장소 전체 검색으로 확인하라 — 삭제된 export의 잔존 import는
  하드 빌드 브레이크. (2건, P1)
- dev/디버그 경로가 런타임(실사용자 상태 쓰기 금지)+빌드(컴파일 타임 플래그로 데드코드 제거) 양쪽에서
  격리됐는지, glob 제외가 tracked 경로 자체(submodule pointer)를 놓치는지, dev 가드가 형제 제출 경로에
  누락됐는지 본다. (7건)
- 배포처가 결정됐는데 어댑터·설정·프로덕션 origin env·의존성 transport(git+ssh)·시크릿 스토어·CI node가
  미준비면 → "프로덕션 빌드 불가"·localhost 누출·SSH 없는 CI 설치 실패. `|| true`로 삼킨 설치 실패,
  라이브러리 보안 기본값(implicit linking) 미명시도 잡는다. (11건, P1)
- 프리렌더/정적 산출물이 클라 런타임 보정 없이 단독 완전한지(footer·hreflang·og:locale·404), URL 재작성
  시 query·hash를 보존하는지 본다 — 크롤러·새 탭·no-JS는 보정을 전부 우회한다. (4건)
- **시크릿 값은 어떤 커밋 파일에도 넣지 마라.** 이름·주석만 커밋, 값은 배포 플랫폼 시크릿 스토어로.
  시크릿 담는 로컬 파일 패턴은 `.gitignore`에 선등록. (원칙)

## 후속 트래킹

- 이번 리뷰에서 valid하지만 이번 diff에 안 얹기로 한 후속(인덱스·페이지네이션·영속화 보강)은 이슈로
  등록하고 스레드에는 이슈 링크로 답한다. 조용한 드랍이 아니라 트래킹이 전제다.
- **BLOCKER(라이브 운영 영향)만 리뷰 루프를 늘리고, COSMETIC(주석·문서 정합·네이밍)은 놓치지 않되 수렴
  후 배치 처리**한다 — 무한 리뷰 루프 방지(`$pr-self-loop` 심각도 정책과 동일 축).
