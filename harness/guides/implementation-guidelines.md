두 소비 프로젝트(웹 퀴즈 앱·보드형 웹 게임)의 PR 76건을 조사해, 그중 56건에 달린 자동
코드리뷰 인라인 지적 264건(P1 41건)을 전수 클러스터링(커버리지 264/264)하고, 리뷰

리뷰에서 반복 지적된 결함의 일반화이며, 각 규칙 끝의 `(N건)`은 근거 지적 수, `P1`은
치명 등급 포함을 뜻한다.

`$feature-develop`의 설계·구현·테스트 단계와 role 문서(`domain-engineer`,
`ui-engineer`, `test-engineer`)가 이 문서를 얇게 참조한다(복제 금지).

## 로딩 규칙 (토큰)

**전체를 항상 로드하지 않는다.** §0 코어 원칙 + 아래 표면 인덱스에서 현재 작업이
건드리는 섹션만 골라 읽는다. 설계 단계(architect)가 섹션을 선택해 구현 브리핑에
포함시키면, fan-out된 서브에이전트는 이 파일을 다시 열지 않아도 된다.

## 0. 코어 원칙 (항상 적용)

1. **스펙·문서·문구는 코드와 같은 변경에서 움직인다.** 한 곳에만 남은 옛 서술은
   미래의 회귀나 사용자 기만으로 돌아온다.
2. **같은 사실은 한 곳에서만 정의한다.** 두 곳에서 계산되는 사실은 반드시 드리프트한다.
3. **경계로 들어오는 값은 전부 불신한다.** 정상 입력이 아니라 적대적 입력이 설계
   기준이다. 방어 코드 자체도 bounded여야 한다(검증하다 OOM 나면 방어가 아니다).
4. **한 방향만 만든 기능은 미완이다.** 저장은 복원까지, 설정은 해제까지, 진입은
   이탈까지, 캐시는 무효화까지가 한 단위다.
5. **완료 선언은 대조 뒤에만 한다.** 스펙 한정어 문구 단위 대조 + 극단 케이스(최장
   입력·최소 뷰포트·다른 로케일·직접 URL 진입)를 확인하고 선언한다.
6. **"유저 적을 때는 괜찮다"는 없다.** 규모·성공을 목표로 하면서 확장성 결함을
   미루는 것은 목표와의 모순이다. 규모가 오기 전에 심는다.

## 1. 스펙·문서·사용자 문구 동기화

코드가 바뀌는 순간 그 사실을 서술하는 모든 산출물이 같은 변경 단위에서 함께 움직여야 한다.

- 동작·수치·규칙을 바꾸면 그것을 서술하는 모든 문서(PRD·ADR·패치노트·위키·테스트
  설명·후속 TODO)를 repo-wide 검색으로 찾아 같은 변경에서 일괄 갱신하라 — 옛 서술이
  정본으로 남으면 후속 작업자가 제거된 기능을 재도입한다. (9건)
- 승인된 스펙의 한정어("최초 1회만"·"루트 진입에만"·포함/제외 목록)는 구현 완료 선언
  전에 문구 단위로 코드와 대조하고, 조건마다 대응 장치가 하나씩 존재하는지 확인하라 —
  "대체로 동작함"은 한정어 하나가 빠진 채 배포된다. (8건·P1)
- 미구현 기능을 약속하거나 실제 판정 로직과 다른 규칙을 서술하는 사용자 노출 문구를
  전수 검색으로 제거·동기화하고, 모든 로케일에 동일하게 반영하라. (8건)
- 문서가 약속한 재현 스크립트·자동 연결 계약은 코드 변경 시 함께 갱신하고 실제 실행,
  배선 끝단까지 검증하라 — 계약 문구만 남으면 에러 없이 조용히 어긋난다. (3건)
- UI 표면·설정·플랫폼을 교체·이관할 때는 기존 항목을 인벤토리로 만들어 전수
  대조하라 — "핵심만 옮기기"는 누락을 조용한 회귀로 만든다. (3건)

## 2. 단일 출처와 파생 일관성

- 사전 판정(가능 여부)·표시·계측은 실제 실행 엔진과 같은 규칙(가능하면 같은 코드
  경로)을 공유하라. UI 선제 차단으로 도메인의 실패 분기를 도달 불가능하게 만들지
  마라 — "가능해 보이는데 막히는" 상태와 부당 판정이 생긴다. (9건)
- 도메인 계약(정렬 공식·매칭 범위)·정책 상수·요약 수치·문구 속 설정값은 공유 모듈의
  단일 정의에서 파생하고 하드코딩 복제를 금지하라. (9건)
- 입력에서 파생된 상태는 입력이 바뀌는 즉시 조건 없이 무효화·재계산하라. 로캘 같은
  가변 컨텍스트 의존 표시값을 이벤트 시점 상태로 스냅샷하지 마라. (3건)
- 이중 기록된 사실(카운트·제목·인덱스 등재)은 같은 변경·같은 패스에서 원자적으로
  동기화하라. (4건)
- 문자 길이 단위(코드포인트 vs UTF-16 code unit)·유니코드 정규화(NFC)·수치 표시
  자릿수는 전 계층(입력 제한·카운터·게이트·서버·전 화면)에서 하나의 계약으로
  통일하라 — 계층마다 다른 단위는 같은 값을 다른 키로 만든다. (4건)

## 3. 경계 입력 검증과 서버 방어

공개 경계로 들어오는 모든 값은 신뢰 불가다. 역참조·DB 전달 전에 완전 검증해 4xx로
끝내고, 클라이언트가 강제한 정책은 서버가 동일하게 재강제한다.

- 공개 입력은 역참조·DB 전달 전에 완전 검증해 500이 아니라 400으로 끝내라 — 숫자는
  `Number.isFinite`·정수성·부호·경계 동등값·대상 컬럼 타입 범위(int4/int8)까지 명시
  검사(NaN은 모든 비교에서 false라 가드를 통과해 침묵 전파된다). (9건)
- 클라이언트 공급 가변 크기 필드 전부에 서버측 하드 상한(문자열 길이·배열 원소 수)을
  두고, **본문 파싱 전에** 바이트·청크 수 상한을 강제하라. 길이 검사 자체도 상한+1까지만
  소비하는 bounded 방식으로 — `[...str]` 같은 무제한 검증은 거부 판정 전에 OOM을
  만든다. (9건·P1)
- 저장 계층이 거부하는 값(U+0000, 고립 UTF-16 서로게이트)은 공용 검증 함수로 만들어
  같은 저장소로 향하는 **모든** 입력 경로(본문·검색어·커서·경로 세그먼트)에 일괄
  적용하라 — 한 경로만 고치면 나머지에서 같은 500이 재발한다. (7건)
- 클라이언트 공급 리소스 ID는 엄격한 형식(짧은 길이·URL-safe `^[A-Za-z0-9_-]+$`·예약어
  제외)으로 제한하고, upsert 충돌 분기에서 인증 주체와 기존 행 소유자를 비교해 불일치
  시 거부하라 — 소유자 미검증은 타인 리소스 덮어쓰기다. (4건·P1)
- 클라이언트 UI가 강제하는 도메인 정책(필수값·허용 범위)은 서버 API 경계에서
  재검증하고, 집계·통계에 기록되는 클라이언트 공급 값은 서버의 권위 데이터와 교집합
  검증하라 — 직접 API 호출이 통계를 영구 오염시킨다. (3건·P1)
- 검색·목록 API는 패턴 메타문자(`%`·`_`)를 이스케이프하고, 커서는 정렬 키의 원본
  정밀도를 보존하며(초 절삭 금지), nextCursor를 소비하는 UI 경로와 실제 쿼리 형태에
  맞는 인덱스까지 함께 구현하라. (5건)

## 4. 상태 기계·오류 분류·종결 상태

- 오류 분류 우선순위를 계약으로 명시하고 가드 실행 순서를 일치시켜라 — 무효 입력이
  timeout·게임오버 같은 정상 종료로 승격되지 않게, 전송 계층 실패를 도메인적
  부재(not-found)와 구분하라. (4건)
- 종결(terminal) 상태에서는 모든 변경 입력 경로를 핸들러 진입 지점에서 차단하고
  (오버레이로 가리는 것은 차단이 아니다), 종료 시점 표시값은 명시적으로 freeze하라. (4건)
- 원샷 억제 플래그에는 해제 경로를, 라우트 정체성 파라미터 변경에는 상태 리셋을, 중도
  이탈에는 저장·정산 경로를, 초기 시드에는 모든 진입점 공통 보장을 함께 설계하라 —
  해제 없는 상태는 재진입·직접 URL에서 영구 고착되거나 exploit이 된다. (5건)
- 규칙 엔진에서 주 결과가 무효면 파생 효과도 함께 억제하고, 포괄("전체") 플래그의 적용
  범위는 명시 열거하며, 연속 수치 분류는 exact-match가 아니라 범위 버킷으로 하라. 주입된
  의존성은 복원·리로드 포함 모든 경로에서 일관되게 사용하라(경로별 우회는 복원 불일치를
  만든다). (4건·P1)

## 5. 영속화·복원·동시 쓰기

저장은 쓰기 성공이 아니라 "읽어서 복원되는 왕복"이 완성이다.

- 외부 저장소에서 복원한 데이터는 소비 깊이(원소별 shape)·값 도메인·현재 정본과 대조
  검증하고, 불일치는 기본값 보정이 아니라 **레코드 통째 폐기 후 안전 폴백**으로
  처리하라. 환경 의존 글로벌(localStorage)은 획득 시점부터 가드하라. (8건)
- 저장 API마다 write↔read 짝을 점검하라 — 읽는 소비자 없는 dead write, 영속 경로에
  연결되지 않은 입력 UI를 금지하고, 직렬화 계약은 복원 왕복 테스트로 보장하라 —
  저장되는 척 버려지는 입력은 사용자 기만이다. (4건·P1)
- 완료·확정된 레코드는 상태 우선순위·revision 가드로 뒤늦은·미완료 쓰기로부터
  보호하라(다중 탭 경합; read-check-write는 원자적이지 않다). 복원 시에는 권위 플래그가
  진행 스냅샷을 이긴다. (4건·P1)
- 이탈 경로를 전수 열거(탭 숨김·페이지 종료·SPA 내부 라우팅·언마운트)해 상태를
  flush하라 — `pagehide`는 SPA 내부 이탈에서 발생하지 않는다. unload류 핸들러가 읽는
  미러 상태는 원본 변경 시점에 동기 갱신하고, 라이프사이클 이벤트는 스펙상 실제 발생
  타깃에 등록해 발화 자체를 검증하라(잘못된 타깃 등록은 조용한 무동작이다). (3건·P1)
- 쓰기 "접수"와 "커밋 완료"를 구분해 트랜잭션 완료에서만 성공을 보고하고, 재시도
  가능한 저장은 ID를 제출 상태에 고정해 멱등하게 만들어라. 폴백 저장소는 읽기/쓰기
  대칭과 최신값 우선순위를 함께 정의하라. (4건)
- 조회·뷰모델 파생 함수는 상태를 변경하는 로더를 호출하지 마라(화면을 여는 것만으로
  진행도가 변하는 관찰자 효과). undo 이력에는 그 조작이 바꾼 최소 diff만 저장하라. (2건)

## 6. 비동기·타이머·스케줄링

서로 다른 시계·스케줄러 사이의 실행 순서와 진행 속도를 가정하지 마라.

- 타이머는 틱 누적이 아니라 벽시계 종료 시각과의 차이로 계산하라(백그라운드 스로틀링).
  같은 지속시간을 CSS와 코드에 이중 정의하지 말고 단일 상수·실제 종료
  신호(`animationend`)로 동기화하라. (3건)
- 순차 국면 타이머는 시작 시 동시 예약하지 말고 앞 국면 콜백 안에서 체이닝하라.
  rAF와 setTimeout처럼 다른 스케줄러 사이 실행 순서에 의존하지 마라. (2건)
- 병렬 작업의 정리는 개별 완료를 추적해 마지막 완료 시점에만 수행하라(먼저 끝난
  작업이 나머지를 조기 절단). 일시 효과의 수명은 실제 가시 시점·상태 전이에
  종속시켜라. (4건)
- 주입된 async 의존성의 rejection은 명시적 error 상태+재시도 경로로 흡수하라. 실패를
  catch로 조용히 삼키는 경로를 남기지 마라 — pending에 영구히 갇힌다. (2건·P1)
- 같은 순간에 성립해야 하는 연동 상태 변화는 같은 커밋(이벤트 핸들러·페인트 전
  단계)에서 설정하고, 첫 화면에 반영될 값은 초기 상태·layout effect에서 동기 확정하며,
  CSS transition 활성화는 첫 페인트 다음 프레임으로 미뤄라(첫 로드 플래시). (5건)

## 7. 레이아웃·뷰포트·기하 측정

화면은 극단 입력과 극단 뷰포트에서 깨진다. 기본 로케일·데스크톱에서만 확인하면 숨은 채 배포된다.

- 크기 무제한 콘텐츠에 스케일 하한(minScale)+overflow 클리핑 조합을 쓰지 마라 — 실제
  fit 값을 허용하거나 스크롤 탈출구를 남기고, 최장 입력×최소 뷰포트 경계 케이스를 명시
  검증하라(DOM 존재만 보는 테스트는 시각적 클리핑을 못 잡는다). (4건)
- 고정 크기 요소의 세로 스택·nowrap 행은 최소 지원 폭(320px)·낮은 높이(가로 모드)·가장
  긴 로케일 라벨 조합에서 합산 크기를 검증하고, 핵심 요소는 남은 공간에 맞춰 수축하게
  하라. (4건)
- 앵커 rect·offsetTop 같은 기하 스냅샷을 캐시해 재사용하지 마라 — 앵커·뷰포트가
  움직이는 모든 이벤트(리사이즈·회전·소프트 키보드·스크롤)에서 재측정하고, 모바일
  오버레이 배치는 window 치수가 아니라 `visualViewport` 크기·오프셋 기준으로 계산하라. (6건·P1)
- 중첩 오버레이의 최대 크기는 부모가 아니라 "기준 요소부터 가시 뷰포트 끝까지 남은
  공간"으로 계산하고, 높이 제한 컨테이너에는 `min-height:0`+`overflow-y:auto`로 내부
  스크롤 경로를 보장하며, 앵커 정렬로 최소 사용 가능 높이를 못 채우면 전체 영역 폴백으로
  전환하라 — 스크롤 영역이 0으로 붕괴하면 마지막 항목에 영원히 도달 불가다. (6건)
- 크기 측정은 이전 인라인 제약을 해제한 자연 크기와 최종 제약 상태 둘 다에서 수행하고,
  동적 배치는 화면을 실제 차지하는 요소 전부(absolute 자식 포함)를 측정하며 내용 변화
  시 재측정(ResizeObserver)하라. (5건)
- 카메라·스크롤 목표는 "특정 지점 중앙 정렬"이 아니라 "관심 콘텐츠 바운딩 박스가 가시
  사각형에 전부 들어감"을 불변식으로 검증·보정하고, 보간 진행 중 좌표계를 재기준화하지
  마라. (2건·P1)
- 자릿수가 늘어나는 숫자·지연 로드 이미지에는 최종(최대) 크기 기준으로 공간을 미리
  예약하라(고정 폭·aspect-ratio) — layout shift 방지. (2건)
- SPA의 모든 화면 전환(라우트 교체·내부 상태 전환·컨테이너 내 콘텐츠 교체)에서
  스크롤을 명시적으로 상단 리셋하라 — 해시 라우팅·내부 전환은 브라우저가 리셋해 주지
  않고, `preventScroll`로 제거한 암묵적 스크롤 부작용은 명시 코드로 대체해야 한다. (4건)

## 8. 접근성·포커스·입력 이벤트

접근성은 속성 부착이 아니라 실제 키보드·스크린리더 경로로 검증되는 동작이다.

- 포커스된 요소를 언마운트·비활성화하는 모든 상태 전환(제출·닫기·화면 전환)에서 새로
  남는 의미 있는 요소로 포커스를 명시 이동·복귀시키고, 복원 대상이 여전히 DOM에
  연결돼 있는지 확인하라 — body로 유실된 포커스는 탐색을 처음부터 다시 시킨다. (8건)
- 네이티브 click 대신 pointerdown/keydown으로 활성화를 구현하면 브라우저 기본
  보장(`event.repeat` 필터·primary 버튼 한정·보조기술 합성 click)을 전부 재구현해야
  한다. 가드는 같은 동작에 도달하는 **모든** 이벤트 경로에 적용하라. (4건)
- IME 조합 이벤트(compositionend·keyCode 229·isComposing)의 발생 순서를 신뢰하지 말고
  자체 추적 상태로 판정하라. 가능한 이벤트 순서 조합을 나열해 제출 유실 경로가 없음을
  점검하라 — 조합 입력(한글)의 제출 유실은 브라우저·플랫폼마다 다르게 터진다. (2건·P1)
- ARIA·키보드 시맨틱은 플랫폼 실제 동작 기준으로 검증하라 — 커스텀 활성화 요소는
  Enter+Space 둘 다, `aria-hidden`은 대체 접근 수단 확인 후에만, 포커스 트랩 후보에서
  `tabindex=-1`·`aria-hidden` 요소 제외, 흐림(blur) 효과가 포커스 링을 지우지 않게 하고,
  구조 요소 제거 전 셀렉터 참조 계약을 검색하라. (7건)
- 반복 이벤트 피드백(애니메이션 재생·라이브 영역 공지)은 실제 DOM 변화가 있어야
  발생한다 — 세대 카운터·key 재부착으로 매 이벤트 관찰 가능한 변화를 강제하고, 라이브
  영역은 빈 상태로 마운트 후 채워라. (3건)
- `prefers-reduced-motion`은 모든 모션 채널(transition·인라인 스타일 포함)에 적용하고
  축소 환경을 실제 활성화해 최종 cascade 기준으로 검증하라. 대체 경로의 최종 화면이
  "모든 정보를 담은 완전한 상태"를 독립 충족하는지 확인하라. (3건)
- 항상 접근 가능해야 하는 컨트롤(탈출구·CTA)과 횡단 요구사항(법적 고지)은 공통
  레이아웃 수준에 배치하고 모든 화면 상태(오버레이 겹침·모든 진입 경로)에서 실제 조작
  가능한지 검증하라. 실패 안내는 실제 수행 가능한 복구 수단과 함께 제공하라. (4건)
- 지원을 선언한 모든 로케일을 검색 매칭·표시 텍스트·aria-label·툴팁까지 전 문자열 소비
  지점에 전수 적용하고, 기존 로케일 헬퍼를 두고 원본 값을 직접 쓰는 지점을 남기지 마라 —
  일부 언어만 매칭하면 그 로케일 사용자는 기능 자체를 못 쓴다. (2건·P1)

## 9. 데이터 생성 파이프라인·캐시 수명주기

생성 산출물과 캐시는 소스 리비전·산출 스키마·생성 로직 버전의 함수다. 사람의 기억에
의존하는 무효화는 설계 결함이다.

- 캐시 키에 소스 리비전·산출 스키마·생성 로직 버전을 포함해 자동 무효화하라. 캐시 도입
  시 최초 채움(제어권 획득 전에 들어온 요청의 소급 반영 포함)과 배포 시 무효화까지 전
  수명주기를 설계하라 — "`--fresh`를 기억해야 한다"는 반드시 실패한다. (5건)
- 파이프라인의 포함/필터 정책을 바꾸면 같은 파이프라인의 다른 강제 지점(스키마
  검증기)과 캐시 버전을 같은 변경에서 함께 갱신하라. (2건·P1)
- 재현성이 전제인 파이프라인은 참조하는 모든 외부 소스를 커밋 SHA·태그로 고정하고,
  재생성 결과가 커밋된 산출물과 미세 표기까지 일치하는지(왕복 재현성) 검증하며, 변형
  병합 시 모든 이름 필드를 정본 표기로 정규화하라. (3건)
- 그래프·변형이 있는 엔터티의 파생 속성은 순회 범위(계보 전체 vs 자기 노드, 형제 분기
  누출 금지)와 매칭 키(완전 식별자)를 스펙과 대조해 정의하고, 로직·표시에 쓰는 속성은
  변형 수준의 명시적 데이터로 확정하라 — 부모 상속·명명 휴리스틱 금지. (7건·P1)
- 데이터를 복수 풀로 분할하면 모든 소비처(조회·게이트·집계·라벨)가 합집합/부분집합 중
  무엇을 쓰는지 명시하고 일관 적용하라. 엔터티 파생 표시명은 단사성(서로 다른 엔터티가
  같은 이름으로 붕괴하지 않음)을 자동 중복 검사로 보장하라. (4건·P1)
- 생성·측정의 실패는 조용히 삼키지 말고 불변식 위반으로 명시 집계하라(비율 분모는 실제
  성공 수). 고정 폴백은 무작위 재시도 소진 뒤 최후에만 쓰고, 불변식을 깨는 경계 케이스는
  국소 패치가 아니라 불변식 보존 변환으로 고쳐라. (3건)

## 10. 검증 게이트·릴리스·전환 절차

게이트는 대리 지표가 아니라 다운스트림이 실제로 요구하는 불변식을 직접 검증해야 한다.

- 단계별 게이트(생성→로드→사용)는 개수·존재 같은 대리 지표가 아니라 다운스트림 실사용
  불변식을 직접 검증하라. 불변식을 보장 못 하는 조회 함수는 fallback 대신 명시적 실패를
  반환하게 하라 — "통과했지만 못 쓰는" 데이터가 사용자 앞에서 터진다. (4건·P1)
- **게이트가 무엇을 검증하지 않는지 알라.** 예: 프레임워크 빌드의 타입 패스가 테스트
  파일을 제외하면 gate green ≠ 타입 안전이다 — `tsc --noEmit`(동등물)을 커밋 전 별도로
  돌려라.
- DNS 위임·프록시 전환처럼 실행 즉시 실트래픽이 바뀌는 단계는 준비와 활성화를 분리하고,
  모든 검증(레코드 대조·인증서 active)이 전환보다 반드시 앞에 오도록 절차를 재배열하라.
  자동 스캔 결과 대신 명시적 대조 게이트를 두어라. (4건·P1)
- 리다이렉트 문법·경로 매칭·URL 정규화처럼 벤더마다 다른 세부 동작은 다른 플랫폼
  관례를 이식하지 말고 공식 문서·실측으로 검증하라. 플랫폼의 정규화 결과가
  canonical·사이트맵 등 자체 생성 URL과 어긋나지 않는지 최종 URL 기준으로 대조하라. (3건·P1)
- 심볼 삭제·리네임은 모든 참조를 같은 변경에서 전환하고 커밋 전 타입체크·빌드를
  통과시켜라. 새로 정의한 스타일·리소스는 실제 참조·적용 지점까지 연결됐는지 저장소
  전체 검색으로 확인하라 — 참조 없는 추가는 조용히 누락된 채 통과된다. (2건·P1)
- 개발·디버그 전용 경로는 런타임(실사용자 영속 상태 쓰기 금지)과 빌드(컴파일 타임
  플래그로 데드코드 제거) 양쪽에서 격리하라. (2건)
- 배포처가 결정됐으면(ADR) 코드측 배포 어댑터·빌드 스크립트는 계정·시크릿 없이도 미리
  준비하라 — 미루면 "프로덕션 빌드 불가" 상태로 방치된다. 배포 플랫폼별 제약(런타임
  지시자·미들웨어 제한)은 구현 전 공식 문서로 확인하라(추측 금지).
- 프리렌더·정적 산출물은 클라이언트 JS의 런타임 보정 없이 단독으로 완전해야 한다 —
  크롤러·새 탭·no-JS 소비자는 보정을 전부 우회한다. URL 재작성 시 바꾸는 부분만
  교체하고 query·hash를 보존하라. (3건)
- **시크릿 값은 어떤 커밋 파일에도 넣지 마라.** 이름·주석 문서화만 커밋하고 값은 배포
  플랫폼의 시크릿 스토어로 주입하라. 시크릿을 담는 로컬 파일 패턴은 `.gitignore`에
  선등록하라.
- **테스트·문서에 raw 제어문자를 임베드하지 마라.** raw NUL·고립 서로게이트 바이트가
  들어가면 git이 파일을 binary로 취급해 이후 검색·diff에서 내용이 사라진다 —
  `\u0000` 같은 이스케이프 리터럴만 쓰고, `grep -caP '\x00' <file>` == 0으로 검증하라.

## 후속 트래킹

- 이번 변경에 안 얹기로 한 정당한 후속(인덱스·페이지네이션·영속화 보강)은 이슈로
  등록해 근시일 처리로 트래킹하고, 리뷰 스레드에는 이슈 링크로 답한다.
- 리뷰가 무한히 쌓이면 valid 지적을 후속 이슈로 분리하고 피처를 매듭짓는 판단도
  필요하다(무한 리뷰 루프 방지). 단, 분리는 트래킹이 전제다 — 조용한 드랍이 아니다.
